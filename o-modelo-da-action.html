    3. O modelo da action

    Uma action precisa de informações enviadas pelo navegador: os parâmetros da URL ([?name=martin&age=42]), os campos de formulário e os parâmetros de rota. O curso de origem se refere a todas essas informações como o modelo da action. Este capítulo mostra como o [ASP.NET Core] fornece essas informações à action, as converte para o tipo correto e as valida. Esse processo se chama model binding ([model binding]).

    using Microsoft.AspNetCore.Mvc;

namespace Example07.Controllers;

[Route("parameters")]
public class ParametersController : Controller
{
    // /parameters/action01?name=martin: o parâmetro de URL [name] -> o parâmetro de action [name]
    [HttpGet("action01")]
    public string Action01(string? name)
    {
        return $"name = [{name}], of type {name?.GetType().Name ?? "null"}";
    }

    // /parameters/action02?age=42: o valor é CONVERTIDO para o tipo do parâmetro
    [HttpGet("action02")]
    public string Action02(int age)
    {
        return $"age = [{age}], of type {age.GetType().Name}, ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parameters/action03?age=42: int? distingue um parâmetro ausente (null) de um zero
    [HttpGet("action03")]
    public string Action03(int? age)
    {
        return $"age = [{age?.ToString() ?? "null"}], ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parameters/action04?page=2: um valor padrão se o parâmetro estiver ausente
    [HttpGet("action04")]
    public string Action04(int page = 1)
    {
        return $"page = [{page}]";
    }

    // /parameters/action05?q=nest: [FromQuery(Name = ...)] quando os nomes diferem
    [HttpGet("action05")]
    public string Action05([FromQuery(Name = "q")] string? search)
    {
        return $"search = [{search}]";
    }

    // /parameters/action06?name=martin&age=42: todos os parâmetros de uma vez
    [HttpGet("action06")]
    public Dictionary<string, string> Action06()
    {
        return Request.Query.ToDictionary(p => p.Key, p => p.Value.ToString());
    }
}

    Vamos analisar este código:

    • linhas 10–12: o model binding associa os parâmetros da action aos dados da requisição pelo nome: o parâmetro [name] da action recebe o valor do parâmetro [name] da URL (a parte que vem após o [?], chamada de query string ou [query string]). O tipo [string?] indica que o valor pode estar ausente; nesse caso, ele é [null]. [name?.GetType().Name ?? "null"]: o nome do tipo do valor ou a string ["null"] se o valor for [null] (o operador [??] fornece um valor de substituição);
    • linhas 17–19: o parâmetro é declarado com o tipo [int]: o model binding converte a string recebida (["42"]) em um número. Se a conversão falhar ([?age=abc]), a action é executada mesmo assim, usando o valor padrão do tipo (0 para um [int]), e a falha é registrada em [ModelState]; o estado do model binding — [ModelState.IsValid]— passa então a ser [false];
    • linhas 24–26: com o tipo [int?] (um inteiro “anulável”), um parâmetro ausente é representado como [null], e não como 0: isso permite distinguir entre “sem idade” e “idade 0”;
    • linhas 31–33: um valor padrão de [C#] substitui um parâmetro ausente;
    • linhas 38–40: o atributo [[FromQuery(Name = "q")]] especifica onde procurar o valor (na URL) e sob qual nome: o parâmetro [search] da action recebe o parâmetro [q] da URL;
    • linhas 45–47: [Request.Query] dá acesso a todos os parâmetros da URL, sem nenhum mapeamento ou conversão. [ToDictionary] ([LINQ]) cria a partir deles um dicionário, serializado em JSON.

    As aspas em torno da URL são necessárias quando ela contém o caractere [&], que tem um significado específico para o console. Observe que:

    • um parâmetro é vinculado pelo nome, independentemente de maiúsculas e minúsculas ([?NAME=martin] também é válido);
    • seu valor é convertido para o tipo declarado. Essa é uma diferença importante em relação ao [NestJS], no qual o tipo de um parâmetro era apenas uma declaração ([TypeScript]) removida em tempo de compilação;
    • uma conversão impossível não causa erro: a action é executada com um valor padrão, e cabe a ela verificar [ModelState.IsValid]. Um tipo “anulável” ([int?]) evita que um valor ausente ou inválido seja confundido com 0.

    Caracteres acentuados e espaços são codificados em uma URL ([%C3%A9] para [é] etc.): o [ASP.NET Core] os decodifica antes do binding.

    using System.ComponentModel.DataAnnotations;

namespace Example08.Models;

// o modelo da action: uma classe em que cada propriedade carrega suas restrições
public class PersonModel
{
    [Required(ErrorMessage = "the name is required")]
    [StringLength(20, MinimumLength = 2, ErrorMessage = "the name must have 2 to 20 characters")]
    public string? Name { get; set; }

    [Required(ErrorMessage = "the age is required")]
    [Range(0, 150, ErrorMessage = "the age must be between 0 and 150")]
    public int? Age { get; set; }

    [Required(ErrorMessage = "the title is required")]
    [AllowedValues("Mr", "Mme", "Melle", ErrorMessage = "unknown title")]
    public string? Title { get; set; }

    // opcional: sem [Required]
    [EmailAddress(ErrorMessage = "invalid email address")]
    public string? Email { get; set; }
}

    Vamos comentar este código:

    • linha 1: o namespace dos atributos de validação;
    • linha 10: cada parâmetro esperado é uma propriedade pública ([{ get; set; }]: ela pode ser lida e gravada). O model binding cria um objeto [PersonModel] e depois preenche cada propriedade com o parâmetro de mesmo nome;
    • linhas 8–9: o nome é obrigatório ([[Required]]) e deve ter entre 2 e 20 caracteres ([[StringLength]]). Cada atributo aceita uma mensagem de erro personalizada ([ErrorMessage]). As propriedades são declaradas “anuláveis” ([string?], [int?]): um parâmetro pode estar ausente de uma requisição, e [[Required]] impõe essa obrigatoriedade;
    • linhas 12–14: a idade é convertida em um inteiro, é obrigatória e deve estar entre 0 e 150 ([[Range]]);
    • linha 17: o título deve pertencer a uma lista de valores ([[AllowedValues]], introduzido com o [.NET] 8);
    • linha 21: o endereço de e-mail é opcional (sem [[Required]]); se informado, deve ser válido.

    using System.Net;
using Example09.Models;
using Microsoft.AspNetCore.Mvc;

namespace Example09.Controllers;

// sem [ApiController]: a action é SEMPRE executada, e é ela que
// decide o que fazer com um modelo inválido
[Route("persons")]
public class PersonsController : Controller
{
    [HttpGet("action01")]
    public ContentResult Action01(PersonModel person)
    {
        // ModelState: o resultado do binding E da validação do modelo
        if (ModelState.IsValid)
        {
            return Page($"<p>Welcome {person.Title} {person.Name} ({person.Age} years old)</p>");
        }
        // os erros, campo a campo
        var items = ModelState
            .Where(field => field.Value!.Errors.Count > 0)
            .Select(field => $"<li>{field.Key}: {string.Join(", ", field.Value!.Errors.Select(e => e.ErrorMessage))}</li>");
        return Page($"<p>The form contains errors:</p><ul>{string.Join("", items)}</ul>");
    }

    // uma página HTML (código 200 nos dois casos)
    private ContentResult Page(string html) => Content(html, "text/html; charset=utf-8");
}

    Vamos comentar este código:

    • linha 9: sem [[ApiController]], a action é executada sempre, quer o modelo seja válido ou não. Um parâmetro de tipo classe é procurado em todos os lugares: na URL, nos campos do formulário e na rota;
    • linha 13: o model binding e a validação foram realizados antes da execução da action: o objeto [person] está preenchido, e [ModelState] contém os eventuais erros;
    • linhas 16–18: sem erros: uma página de boas-vindas;
    • linhas 21–23: caso contrário, a lista de erros. [ModelState] é um dicionário em que cada chave é o nome de um campo ([Name], [Age]...) e cada valor é o estado desse campo, junto com sua lista de erros ([Errors]). Os métodos [LINQ], [Where] (filtrar) e [Select] (transformar) mantêm os campos com erros e geram uma linha HTML por campo. [!] informa ao compilador que um valor não é [null];
    • linha 24: uma página que lista os erros;
    • linha 28: nos dois casos, a resposta é uma página HTML, com código de status 200.

    using System.ComponentModel.DataAnnotations;

namespace Example10.Models;

// IValidatableObject: uma validação escrita em C#, para o que os atributos
// não conseguem expressar (aqui: CADA elemento da lista)
public class ChoiceModel : IValidatableObject
{
    private static readonly string[] Colors = ["red", "green", "blue"];

    [MinLength(1, ErrorMessage = "choose at least one color")]
    public List<string> Color { get; set; } = [];

    public IEnumerable<ValidationResult> Validate(ValidationContext context)
    {
        foreach (var color in Color.Where(c => !Colors.Contains(c)))
        {
            // yield return: o método retorna os erros um a um
            yield return new ValidationResult($"unknown color: {color}", [nameof(Color)]);
        }
    }
}

    Vamos comentar este código:

    • linha 7: a classe implementa a interface [IValidatableObject]: uma validação escrita em [C#] para o que os atributos não conseguem expressar;
    • linha 11: [[MinLength(1)]]: a lista deve ter pelo menos um elemento;
    • linhas 14–18: o método [Validate], chamado pela validação depois dos atributos, verifica cada cor. Ele devolve um erro ([ValidationResult]) para cada cor desconhecida, indicando o campo em questão. [yield return] devolve os erros um a um, sem criar uma lista.

    using System.Globalization;
using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Example12.Binding;

// um "model binder": transforma uma data francesa "23/09/2026" em um DateOnly
public class DateFrBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext context)
    {
        // o valor bruto, encontrado na URL, no formulário, na rota...
        var raw = context.ValueProvider.GetValue(context.ModelName).FirstValue;
        if (DateOnly.TryParseExact(raw, "dd/MM/yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out var date))
        {
            // sucesso: o valor que a action receberá
            context.Result = ModelBindingResult.Success(date);
        }
        else
        {
            // falha: um erro no ModelState ("31/02/2026" também é rejeitada)
            context.ModelState.AddModelError(context.ModelName, $"[{raw}] is not a valid dd/mm/yyyy date");
        }
        return Task.CompletedTask;
    }
}
    • linha 7: um model binder implementa a interface [IModelBinder];
    • linha 9: o método [BindModelAsync] recebe o contexto de binding: o nome do parâmetro ([ModelName]), as fontes de valores ([ValueProvider]: a URL, o formulário, a rota...), [ModelState]...;
    • linha 12: o valor bruto do parâmetro ([FirstValue]: o primeiro, se houver vários);
    • linhas 13–16: [DateOnly.TryParseExact] converte uma string no formato [dd/mm/yyyy] para [DateOnly] (uma data sem hora) e devolve [false] se isso for impossível, inclusive para uma data que não existe (31/02/2026). Em caso de sucesso, [ModelBindingResult.Success(date)] fornece o valor que a action receberá;
    • linha 21: se a operação falhar, um erro é adicionado a [ModelState];
    • linha 23: o método é assíncrono por natureza ([Task]), mas não há nada a esperar: ele devolve uma tarefa que já foi concluída.

    using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Example12.Binding;

// o idioma preferido do navegador, lido do cabeçalho
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LanguageBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext context)
    {
        var header = context.HttpContext.Request.Headers.AcceptLanguage.ToString();
        var first = header.Split(',')[0].Trim();
        var language = first.Length >= 2 ? first[..2].ToLowerInvariant() : "fr";
        context.Result = ModelBindingResult.Success(language);
        return Task.CompletedTask;
    }
}
    • linha 11: o cabeçalho [Accept-Language], que especifica os idiomas preferidos do usuário;
    • linhas 12–13: as duas primeiras letras do primeiro idioma. [first[..2]] é um intervalo ([range]): os caracteres de índices 0 e 1.

    using System.ComponentModel.DataAnnotations;

namespace Example12.Binding;

// um atributo de validação "caseiro": [NoSpace]
public class NoSpaceAttribute : ValidationAttribute
{
    public NoSpaceAttribute() : base("the {0} field must not contain any space")
    {
    }

    public override bool IsValid(object? value)
    {
        // null é aceito: exigi-lo é tarefa de [Required]
        return value is not string text || !text.Contains(' ');
    }
}
    • linha 6: um atributo de validação herda de [ValidationAttribute]. Por convenção, o nome de uma classe de atributo termina com [Attribute], sufixo que é omitido na prática: [[NoSpace]];
    • linha 8: a mensagem de erro padrão, passada à classe pai. [{0}] será substituído pelo nome do campo;
    • linhas 12–15: a regra. [value is not string text]: se o valor não for uma string ([null], por exemplo), ele é aceito; caso contrário, é atribuído à variável [text], que não deve conter nenhum espaço. O estudo de caso tem um atributo desse tipo: [[OneOf]].

namespace Example12.Controllers;

[Route("examples")]
public class ExamplesController : Controller

    // /examples/schedule?day=23/09/2026: um model binder personalizado
    [HttpGet("schedule")]
    public IActionResult Schedule([ModelBinder(typeof(DateFrBinder))] DateOnly day)
    {
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState[nameof(day)]!.Errors[0].ErrorMessage);
        }
        return Ok($"schedule for the day [{day:yyyy-MM-dd}]");
    }

    // /examples/hello: um parâmetro que não vem da URL, mas de um cabeçalho
    [HttpGet("hello")]
    public string Hello([ModelBinder(typeof(LanguageBinder))] string language)
    {
        return language == "en" ? "Hello!" : "Bonjour !";
    }

    // /examples/search?keyword=aspnet: um atributo de validação personalizado
    [HttpGet("search")]
    public IActionResult Search([NoSpace] string? keyword)
    {
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState[nameof(keyword)]!.Errors[0].ErrorMessage);
        }
        return Ok($"search for [{keyword}]");
    }
}

    • linha 29: um atributo de validação também pode ser aplicado diretamente a um parâmetro de action.

    3.6.5. Conclusão

    O modelo da action é construído pelo model binding a partir da requisição: parâmetros de rota, URL, campos de formulário, corpo JSON e cabeçalhos. Os valores são convertidos para os tipos dos parâmetros e depois validados com base nos atributos. O resultado dessas duas etapas é armazenado em [ModelState]. Para um servidor JSON, [[ApiController]] rejeita automaticamente um modelo inválido; para uma aplicação HTML, a própria action testa [ModelState.IsValid] (exemplo 09) para que o formulário possa ser reexibido. Esse é o assunto do próximo capítulo.
